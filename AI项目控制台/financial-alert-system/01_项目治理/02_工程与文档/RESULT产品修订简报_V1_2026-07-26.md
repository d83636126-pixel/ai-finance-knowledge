# RESULT 产品修订简报 V1

## 0. 一页结论

V3.0 已证明 RESULT 的工程机制可以运行，但当前页面更像一张完整的审计表，还没有把用户最关心的复盘结论放到最前面。

修订后的产品定位：

> RESULT 不是研究报告生成器，而是一张“事件收尾卡”：帮助用户在事件发生后快速确认实际结果、市场反应、原判断偏差，以及下一次同类事件应提前观察什么。

本轮只修产品组织和用户路径，不再扩展技术门禁，不证明预测力，也不进入 REGISTRY / BADGE。

---

## 1. 用户为什么要打开 RESULT

用户打开 RESULT，不是为了完成一组字段，也不是为了查看系统是否通过六项机制检查，而是为了回答四个问题：

1. **实际发生了什么？**
2. **市场在关键窗口如何反应？**
3. **原来的判断或传播路径哪里成立、哪里偏离？**
4. **下一次同类事件应该提前看什么？**

如果页面不能在短时间内给出这四个答案，即使字段、标签和验证机制都完整，也没有形成足够的产品价值。

### 1.1 核心用户任务

```text
事件已经发生
  → 打开研究记录
  → 确认实际结果和可靠来源
  → 查看关键市场窗口
  → 对照原判断或声明“没有事前判断”
  → 留下一条可复用观察
  → 保存事件收尾卡
```

### 1.2 RESULT 不负责的任务

- 不生成长篇研究报告；
- 不证明系统预测正确；
- 不替用户完成因果判断；
- 不把历史复盘升级为 forward / unseen；
- 不承载跨事件统计、榜单或徽章；
- 不要求用户为了验收而填写所有可选字段。

## 2. 最短真实使用路径

### 2.1 唯一主入口

RESULT 的主入口应放在“统一研究记录”中，并且只在事后门禁允许时显示为主要动作：

```text
日历 / Inbox
  → 纳入研究
  → 统一研究记录
  → 事件已发生，显示「完成事件复盘」
  → RESULT 事件收尾卡
```

独立 RESULT URL 保留为重开和分享入口，但不要求用户记住或主动寻找。

### 2.2 首次完成路径

首次打开只要求四步：

1. **确认事实**：实际值、发生时间、来源；
2. **确认反应**：选择最关键的 1–3 个市场窗口；
3. **确认偏差**：原判断成立、部分成立、不成立或无事前判断；
4. **留下下一步**：写下下次同类事件最值得提前看的一个信号。

完成后自动生成一张可重开的事件收尾卡。

### 2.3 重开路径

重开时默认进入只读摘要，而不是再次展示整张编辑表：

```text
研究记录 / 最近复盘
  → 打开事件收尾卡
  → 先看到四项结论
  → 需要时展开来源、完整窗口和机制详情
```

## 3. 页面结构修订

### 3.1 当前结构的问题

当前 RESULT 依次展示：

- 事件身份；
- 事前区；
- 实际事实区；
- 市场观察区；
- 路径复盘区；
- 可复用结论区；
- 一页摘要；
- 保存区。

该结构机制完整，但存在三个产品问题：

- 用户需要滚动较长距离才看到最终结论；
- 必填、选填和审计信息处于同一层级；
- “填写复盘”和“阅读复盘”使用同一种页面状态。

### 3.2 修订后的默认结构

#### A. 顶部：事件收尾卡

默认首屏直接显示：

- **实际结果**：一句话；
- **关键市场反应**：最多三项；
- **原判断结论**：成立 / 部分成立 / 不成立 / 无事前判断；
- **下次观察**：一句话；
- 保存状态与最后更新时间。

#### B. 中部：四步编辑区

只在编辑模式展开：

1. 实际事实；
2. 市场窗口；
3. 判断偏差；
4. 下次观察。

模板中非关键字段默认折叠为“补充信息”。

#### C. 底部：证据与边界

以下内容保留，但默认折叠：

- 来源与 captured_at；
- 完整事前快照引用；
- `RETROSPECTIVE / LEGACY_EXPOSED / NO_FROZEN_PRE_SNAPSHOT`；
- 支持与反驳证据；
- 六子机制矩阵；
- checkpoint 模板与 hash；
- `NOT_RESEARCH_VALIDATION`。

这些信息负责可信度，不再成为用户的主要填写任务。

## 4. 保留、删减与重排

### 4.1 必须保留

- canonical `event_id` 与 registry；
- Inbox / 日历纳入；
- 事前只读和事后时间门禁；
- 历史与 legacy 标签；
- 类型级 checkpoint；
- 实际事实和可靠来源；
- 市场观察窗口；
- `SUPPORTED / MIXED / CONTRADICTED / INSUFFICIENT_EVIDENCE`；
- 保存、重开和复制；
- `NOT_RESEARCH_VALIDATION`。

### 4.2 从主界面降级到折叠区

- 六子机制矩阵；
- 模板 hash 和 binding 版本；
- 全量来源元数据；
- 所有可选市场窗口；
- 完整路径支持/反驳列表；
- 工程验收状态。

### 4.3 合并

- “路径复盘”和“可复用结论”合并为“判断偏差与下次观察”；
- “一页摘要”改为顶部事件收尾卡，不再作为页面末尾的重复内容；
- 事件身份与边界标签合并为一条紧凑状态栏。

### 4.4 暂不做

- 自动生成长文；
- 自动因果归因；
- 跨事件排行榜；
- REGISTRY / BADGE；
- 多人协作与权限；
- 研究有效性评分；
- 新一轮技术架构改造。

## 5. 最小数据要求

一条 RESULT 可以保存为“已完成”，只要求：

| 项目 | 最小要求 |
|---|---|
| 实际结果 | 一句话 + 来源 |
| 时间 | 实际发生或发布时间 |
| 市场反应 | 至少一个关键窗口；无数据时明确弃权 |
| 原判断对照 | 四选一；没有事前快照必须选择“无事前判断” |
| 下次观察 | 一条可执行观察，或明确“证据不足” |

其余字段均为补充项，不得阻止用户保存草稿。

### 5.1 两种保存状态

- `DRAFT`：信息尚未齐全，可以继续补充；
- `CLOSED`：五项最小要求完成，形成事件收尾卡。

“已关闭”仅表示本次复盘填写完成，不表示分析正确或研究通过。

## 6. 三条真实事件的产品走查

修订后仍使用三类历史事件走查，但目标从“字段是否齐全”改为“用户是否快速得到可复用答案”。

### 6.1 财报：Alphabet 2025 Q2

用户应能快速看到：

- 财报最关键实际结果；
- 首个交易窗口与下一收盘的反应；
- 原先关注的指标是否仍值得跟踪；
- 下一次财报前需要提前看什么。

### 6.2 政策：美国对等关税

用户应能快速看到：

- 文件内容、生效范围与后续变化；
- 美元、美债、权益和黄金中最关键的反应；
- 哪些反应只是同步波动，不能写成因果；
- 下一次政策公布需要优先确认哪个条款。

### 6.3 地缘：Operation Midnight Hammer

用户应能快速看到：

- 已确认行动、时间锚与来源角色；
- 原油、黄金等资产的关键窗口；
- 哪条传播路径得到支持、哪条证据不足；
- 下一次同类事件应先确认时间、行动范围还是市场开闭市状态。

`nfp_2026_01` 继续只作为 legacy 边界对照，不承担产品价值证明。

## 7. 产品有效性的验证方式

不以新增 smoke 数量作为本次修订成功标准。

Human 用三条真实历史事件完成一次走查，记录以下行为：

| 指标 | 通过标准 |
|---|---|
| 到达 RESULT | 从研究记录最多 1 次点击 |
| 首次理解 | 打开后 30 秒内能说出实际结果、关键反应和下次观察 |
| 完成时间 | 熟悉事件不超过 8 分钟 |
| 必填负担 | 无需填写与本次结论无关的可选字段 |
| 重开价值 | 隔一天重开，仍能直接回答四个核心问题 |
| 复用价值 | 三条事件中至少两条的“下次观察”被 Human 判断为值得保留 |
| 诚实边界 | 无事前快照、legacy、证据不足均清晰可见 |

### 7.1 失败条件

出现任一情况即说明仍需修订：

- 用户打开后先看到机制状态，而不是事件结论；
- 为保存结果被迫填写大量无关字段；
- 摘要只是重复事实，没有“偏差”和“下次观察”；
- 重开后仍需重新查找来源才能理解；
- 历史复盘看起来像提前预测；
- 用户认为以后不会再次打开。

## 8. 建议的下一产品环

只有 Human 批准本简报后，才建立一个新的小产品环。

建议名称：

`PRD-EVENT-RESULT-UX-08`

范围严格限定为：

- 调整 RESULT 信息层级；
- 建立事件收尾卡首屏；
- 四步最小编辑路径；
- DRAFT / CLOSED 状态；
- 三条真实事件 Human 走查。

不包含：

- 新数据源；
- REGISTRY / BADGE；
- 研究评分；
- 新架构包；
- held-out / forward；
- 新一轮完整技术验收。

审核方式：

- 实现过程中不逐段审核；
- 完成三条真实事件走查后，做一次产品验收；
- 非数据损坏、安全、事实错误或主路径阻断的问题登记为技术债。
