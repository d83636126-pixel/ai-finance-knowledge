# 产品发展执行计划 V3.3：同类事件复用与对照

## 0. 定稿结论

V3.3 解决的不是“预测准不准”，而是：

> 准备下一条事件时，能否快速找到过去真实事件留下的事实、偏差和“下次关注”，并把选中的观察点带入新事件。

V3.3 只复用已有收尾卡，不重新生成历史叙事，不输出胜率排行榜。

## 1. 开启前资产条件

V3.3 只有在以下条件满足后才能开环：

- V3.2 已 PASS；
- 至少 6 张可重开的真实事件收尾卡；
- 至少覆盖 3 种事件类型；
- 至少一个类型有 2 张以上可对照收尾卡。

这些资产可以来自已经发生的财报、政策和地缘事件，不等待未来日期。retrospective/legacy 样本可以参与界面机制走查，但必须保留标签，不能作为事前能力证据。

## 2. 用户主路径

```text
打开新事件研究记录
→ 查看“过去相似事件”
→ 选择 2–3 条
→ 对照实际结果、主要偏差和下次关注
→ 勾选可复用观察点
→ 复制为当前事件的准备清单草稿
→ 用户确认后保存
```

## 3. 产品范围

### 3.1 已复盘事件资产库

在 V3.1 台账的“已复盘”基础上提供：

- 按事件类型筛选；
- 按资产、机构、地区或主题搜索；
- 显示事件时间、来源和证据边界；
- 显示是否 retrospective、legacy 或具有真实事前记录；
- 一次选择最多 3 条进行对照。

### 3.2 最小对照视图

对照维度固定为：

1. 事件与实际结果；
2. 主要市场反应；
3. 原研究路径与实际偏差；
4. 哪些观察点有用；
5. 哪些假设失效；
6. 下次关注什么；
7. 证据边界。

空字段必须显示“未记录”，不得由系统补写成确定事实。

### 3.3 观察点复用

- 用户勾选过去收尾卡中的“下次关注”；
- 系统生成当前事件准备清单草稿；
- 每个条目保留来源事件 `event_id`；
- 保存前必须由用户确认；
- 复制不等于预测结论，不自动进入研究评分。

### 3.4 新事件内的相似事件入口

研究记录页面增加一个轻量入口：

- 显示相似事件数量；
- 默认依据显式事件类型和用户筛选，不使用黑箱相似度；
- 无可用历史事件时显示空态，不生成通用建议。

## 4. 执行批次

### Batch A：资产索引

- 从既有 registry 和 V3 收尾卡建立只读索引；
- 事件类型、标签和边界可检索；
- 不复制或迁移原始数据。

### Batch B：对照与复制

- 2–3 条收尾卡并排查看；
- 勾选“下次关注”；
- 带来源复制到当前事件准备清单；
- 保存、重开和撤销复制。

### Batch C：真实复用走查

- 使用至少两条同类财报事件；
- 使用政策或地缘事件验证跨类型不会误匹配；
- 验证 retrospective/legacy 标签始终可见；
- 完成一次集中产品验收。

## 5. PASS 标准

全部满足才可写入 `EVENT_REUSE_V1_PASS`：

- 用户从新事件两次点击以内进入相似事件；
- 可以筛选并选择 2–3 张真实收尾卡；
- 对照字段来自原始收尾卡，不静默补全；
- “下次关注”可选择性复制；
- 复制条目保留来源 `event_id` 和标签；
- 保存后重新打开仍能追溯来源；
- retrospective/legacy 不会显示为事前预测；
- 无相似资产时正确空态；
- 不输出胜率、可靠性 PASS 或方法论已验证。

## 6. 明确不做

- 不做模型相似度搜索；
- 不做自动总结所有历史事件；
- 不做预测胜率、命中率或排行榜；
- 不自动修改当前事件判断；
- 不从小样本推导统计规律；
- 不重写收尾卡；
- 不并行 V3.4。

## 7. 回滚与停止条件

- 相似事件入口可关闭，不影响 V3.2 日常循环；
- 复制失败不得修改当前研究记录；
- 来源链丢失或标签错配属于阻断；
- 若资产条件不足，保持 `sequenced_not_authorized`，不以合成样本伪装产品价值。
