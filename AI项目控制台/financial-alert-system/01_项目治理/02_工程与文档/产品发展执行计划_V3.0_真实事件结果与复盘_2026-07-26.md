# 产品发展执行计划 V3.0：真实事件结果与复盘

## 0. 定稿结论

V3.0 是 V3 的第一个产品能力批次，目标是建立一条诚实、可重用的真实事件结果与复盘路径。

本环回答：

> 一个真实事件怎样从已有摄入层进入研究 registry，怎样保留事前与事后边界，怎样形成可保存、重开和复制的复盘结果？

本环不回答：

> 这套方法是否具有前瞻预测力，或者复盘叙事是否证明了研究方法论可靠？

原定机制验收名：

`EVENT_RESEARCH_RESULT_V1_PASS`

该名称不是一个孤立布尔值。它只能由六个独立、可定位的子机制全部通过后派生。

最终执行中，3 个历史事件达到机制 `PASS`，1 个 `LEGACY_EXPOSED` 样本按规则 `ABSTAIN`，因此没有宣称 `EVENT_RESEARCH_RESULT_V1_PASS`。这不阻断产品范围收尾；最终产品验收为 `RESULT_UX_V1_PASS`。

---

## 1. 产品目标与用户价值

### 1.1 一句话目标

> 用户从真实来源纳入事件后，可以在十分钟内形成一条“事前—实际—反应—路径—结论”复盘，保存后能够重开和复制，同时系统不会把历史复盘包装成提前判断。

### 1.2 用户主路径

```text
官方来源 / RSS / Inbox / 日历
  ↓ 用户确认纳入
稳定 event_id + 来源元数据
  ↓ 幂等写入
现有服务端 registry
  ↓ 打开结果复盘
事前快照 / 无快照标记
  ↓
实际事实 + 市场观察 + 路径复盘
  ↓
保存、重开、复制摘要
```

### 1.3 用户获得的实际增量

- 不再手工伪造一条看似完整的研究记录；
- 历史事件、未来事件和 legacy 记录的边界可见；
- 事后事实不会覆盖事前信息；
- 每条已完成事件形成可复用结果；
- 系统明确告诉用户哪些结论有证据、哪些只能弃权。

## 2. 当前能力基线与本环补齐范围

### 2.1 已经完整接通的路径

当前完整路径为：

```text
GET /api/calendar/upcoming
  → 日历「纳入研究」
  → EventResearchIntegration
  → POST /api/research/records
  → data/event_research_registry/
```

该路径已经具备：

- 稳定 `event_id`；
- 幂等纳入；
- 服务端 registry 真相源；
- 研究记录保存和重开；
- 未来事件事后门禁。

### 2.2 已存在但未完整接到 registry 的路径

现有 Inbox/新闻摄入层已有：

- `/api/ingest/scan-rss`
- `/api/ingest/manual`
- `/api/ingest/classify`
- `/api/ingest/adopt`
- `/api/ingest/pre-report`
- `/api/ingest/post-report`
- `/api/ingest/refresh-evidence`

但当前没有完整证据证明：

```text
Inbox 条目
  → 一键纳入研究
  → 保留来源
  → 幂等写入现有 research registry
```

因此不能把“日历／新闻／inbox 一键收入研究台”的产品方向整体宣称为已经完成。

### 2.3 V3.0 的最小摄入补齐

V3.0 只补：

```text
已存在的 Inbox 条目
  → 用户点击「纳入研究」
  → 生成或复用稳定 event_id
  → 保留 source_url / source_type / published_at / captured_at
  → 幂等写入现有 registry
```

边界：

- 不建立第二套 registry；
- 不重写 RSS 扫描器；
- 不做全自动无人确认采集；
- 不静默把新闻内容当成已确认事实；
- 不保存受限原文；
- 不把普通手工表单包装成“自动导入”。

本环只能宣称：

> 已有摄入层到 research registry 的最小一键接线完成。

- `RETROSPECTIVE`：系统接触事件时结局已知；

- `LEGACY_EXPOSED`：样本已暴露于开发或历史研究过程；
- `research_claim_prohibited=true`：任何本环结果不得升级研究结论。

这些标签不得仅显示在文档中，必须进入机器可读记录和用户可见页面。

## 4. 六个独立子机制

### 4.1 原则

`EVENT_RESEARCH_RESULT_V1_PASS` 不允许直接存储为一个人工布尔字段。

正式结果必须包含六个子机制，每个独立输出：

- `PASS`
- `FAIL`
- `ABSTAIN`
- `NOT_RUN`

每个子机制必须带：

- `reason_codes`
- `evidence_refs`
- `evaluated_at`
- `event_ids`

### 4.2 子机制定义

| 子机制 | 标识 | 独立成功标准 |
|---|---|---|
| 摄入机制 | `RESULT_INGESTION_MECHANISM` | Inbox/日历条目可幂等进入现有 registry，来源字段不丢失 |
| 标签完整性 | `RESULT_LABEL_INTEGRITY` | RETROSPECTIVE、NO_FROZEN_PRE_SNAPSHOT、LEGACY_EXPOSED 等按样本真实状态落盘并可见 |
| 事前/事后隔离 | `RESULT_PRE_POST_ISOLATION` | 事后录入不能修改事前快照；无快照时不得补造 |
| 持久化与重开 | `RESULT_PERSISTENCE_REOPEN` | 保存、关闭、重开和复制摘要保持一致 |
| 声明安全 | `RESULT_CLAIM_SAFETY` | 历史/legacy 结果不能被包装成提前判断或触发 RESEARCH_PASS |
| 时间门禁 | `RESULT_TEMPORAL_GATE` | 未发生、未到发布时间或时间未知事件不能生成事后结果或提前解锁 |

### 4.3 子机制 reason codes

#### 摄入机制

- `registry_write_failed`
- `duplicate_event_created`
- `unstable_event_id`
- `source_url_lost`
- `source_type_lost`
- `published_at_lost`
- `captured_at_lost`
- `inbox_to_registry_not_connected`

#### 标签完整性

- `retrospective_label_missing`
- `no_frozen_pre_label_missing`
- `legacy_exposed_label_missing`
- `label_not_machine_readable`
- `label_not_user_visible`
- `label_conflicts_with_record_state`

#### 事前/事后隔离

- `pre_snapshot_mutated`
- `pre_snapshot_reconstructed_after_outcome`
- `post_fact_written_into_pre`
- `missing_pre_not_declared`
- `revision_overwrote_original`

#### 持久化与重开

- `save_failed`
- `reopen_mismatch`
- `result_event_id_changed`
- `summary_not_reproducible`
- `source_refs_missing_after_reopen`

#### 声明安全

- `historical_presented_as_forward`
- `legacy_presented_as_unseen`
- `research_pass_leak`
- `method_quality_claim_leak`
- `unsupported_accuracy_claim`

#### 时间门禁

- `future_post_allowed`
- `premature_unlock_allowed`
- `unknown_time_fail_open`
- `same_day_future_fail_open`
- `date_window_bypassed`

### 4.4 总判定规则

结构化结果：

```json
{
  "schema_version": "v3-result-mechanism-assessment-v1",
  "submechanisms": {
    "ingestion": {"verdict": "NOT_RUN", "reason_codes": []},
    "label_integrity": {"verdict": "NOT_RUN", "reason_codes": []},
    "pre_post_isolation": {"verdict": "NOT_RUN", "reason_codes": []},
    "persistence_reopen": {"verdict": "NOT_RUN", "reason_codes": []},
    "claim_safety": {"verdict": "NOT_RUN", "reason_codes": []},
    "temporal_gate": {"verdict": "NOT_RUN", "reason_codes": []}
  },
  "overall": {
    "verdict": "NOT_RUN",
    "acceptance_label": null
  }
}
```

判定顺序：

```text
任一子机制 FAIL       → overall FAIL
无 FAIL、任一 ABSTAIN → overall ABSTAIN
存在 NOT_RUN          → overall NOT_READY
六项全部 PASS         → EVENT_RESEARCH_RESULT_V1_PASS
```

报告必须展示六项矩阵，不能只显示 overall。

## 5. 结果复盘产品结构

### 5.1 事件身份区

- `event_id`
- 事件名称与类型
- 生命周期
- 发生时间或窗口
- 来源类型
- `RETROSPECTIVE / LEGACY_EXPOSED` 等边界标签

### 5.2 事前区

- 原始事前快照引用；
- 冻结时间；
- 原始路径引用；
- 原始证据引用；
- 无快照时显示 `NO_FROZEN_PRE_SNAPSHOT`；
- 不允许在结果页编辑原事前内容。

### 5.3 实际事实区

- 实际发生内容；
- 发生/公布时间；
- 官方或可靠来源；
- `captured_at`；
- 修订状态；
- 来源冲突或缺失。

### 5.4 市场观察区

- 指标；
- 观察窗口；
- 起点与终点；
- 方向和幅度；
- 数据来源；
- 缺窗、停市、缺失和异常说明。

市场观察只描述同步变化，不自动证明因果。

### 5.5 路径复盘区

每条路径只允许：

- `SUPPORTED`
- `MIXED`
- `CONTRADICTED`
- `INSUFFICIENT_EVIDENCE`

必须列出支持和反驳证据，禁止只写流畅叙事。

### 5.6 可复用结论区

- 最大偏差；
- 哪个观察点最有用；
- 哪个假设缺乏证据；
- 下次同类事件应提前看什么；
- 仍待确认的事项。

### 5.7 一页摘要

摘要必须包含边界标签和来源，不得删除：

- `RETROSPECTIVE`
- `NO_FROZEN_PRE_SNAPSHOT`
- `LEGACY_EXPOSED`
- `NOT_RESEARCH_VALIDATION`

## 6. 类型级 checkpoint 模板

### 6.1 为什么先冻结类型模板

逐事件设计指标和窗口仍可能受已知结局影响。

因此冻结顺序必须是：

```text
定义事件类型模板
  ↓
冻结模板文件 + SHA-256
  ↓
绑定具体 event_id
  ↓
冻结绑定清单 + SHA-256
  ↓
生成或填写复盘
  ↓
按模板检查
```

不得先看生成结果，再调整模板。

### 6.2 计划工件

类型模板：

`docs/ai-collab/v3_result_checkpoint_templates_v1.json`

事件绑定：

`docs/ai-collab/v3_result_sample_binding_v1.json`

两者均须记录：

- `schema_version`
- `created_at`
- `frozen_at`
- `sha256`
- `supersedes`
- `change_policy`

### 6.3 模板变更规则

- 绑定事件前可以评审模板；
- 绑定后不得原地修改；
- 必须修改时新建版本；
- 新版本不得回写旧事件评分；
- 旧结果保留原模板 hash；
- 生成结果后再修改窗口，结果自动标记 `INVALIDATED_BY_POST_HOC_CHANGE`。

## 7. 四类 checkpoint 模板

### 7.1 财报模板 `earnings_v1`

事实检查：

- 报告期；
- 公布时间；
- 营收；
- 盈利指标；
- 指引或管理层可核实表述；
- 是否存在修订。

市场观察：

- 发行公司股票；
- 相关行业或宽基对照；
- 发布后首个可交易窗口；
- 下一常规收盘；
- T+5 收盘。

弃权：

- 无法确定准确发布时间；
- 盘前/盘后窗口数据不可用；
- 股票停牌或公司行动造成不可比；
- 缺少可靠结果来源。

### 7.2 政策/关税模板 `policy_tariff_v1`

事实检查：

- 法律或行政文件；
- 宣布时间；
- 生效时间；
- 适用范围；
- 例外、暂停或后续修订；
- 文件与媒体摘要是否一致。

市场观察：

- 美元；
- 美债收益率；
- 宽基权益；
- 黄金；
- 与政策直接相关的行业或国家资产；
- 首个可交易收盘、T+1、T+5。

弃权：

- 生效条款仍不明确；
- 多项政策同时公布且无法区分；
- 对应资产没有稳定数据；
- 将同步波动误写为因果结论。

### 7.3 地缘事件模板 `geopolitical_v1`

事实检查：

- 事件发生时间；
- 行动方；
- 已确认行动；
- 已确认目标或范围；
- 后续官方修订；
- 事实与主张的来源角色。

市场观察：

- 原油；
- 黄金；
- 美元；
- BTC；
- 宽基权益；
- 事件后 6 小时、24 小时、首个完整交易日、T+5。

弃权：

- 时间锚无法确认；
- 市场休市且窗口无法对齐；
- 冲突仍在发展、事实持续修订；
- 来源仅有单方主张；
- 观察只能描述相关性，无法支持路径。

### 7.4 宏观发布模板 `macro_release_v1`

事实检查：

- 官方实际值；
- 预期值及来源；
- 前值；
- 修订值；
- 官方发布时间；
- 数据口径。

市场观察：

- DXY；
- 2Y / 10Y 美债；
- 纳斯达克或宽基权益；
- 黄金；
- BTC；
- 发布后 5 分钟、30 分钟、2 小时、T+1。

弃权：

- 预期来源不可验证；
- 关键分钟窗缺失；
- 发布时间或时区不一致；
- legacy 数据无法证明当时可见性。

## 8. 质量信号的语义

### 8.1 输出名称

本环只输出：

`RETROSPECTIVE_ANALYSIS_QUALITY_SIGNAL`

不输出：

- `METHOD_QUALITY_PASS`
- `ANALYSIS_RELIABILITY_PASS`
- `PREDICTION_PASS`
- `RESEARCH_PASS`

### 8.2 信号结果

每条事件及每条路径使用：

- `SUPPORTED`
- `MIXED`
- `CONTRADICTED`
- `INSUFFICIENT_EVIDENCE`

### 8.3 它能说明什么

- 复盘是否遵守预先固定的指标和窗口；
- 事实是否有来源；
- 是否同时呈现支持和反驳证据；
- 数据不足时是否诚实弃权；
- 是否避免明显时间倒置。

### 8.4 它不能说明什么

- 未来事件预测能力；
- 事件选择没有偏差；
- 指标选择完全不受历史认知影响；
- 传播路径具有严格因果效应；
- 模型可用于投资决策。

即使类型模板提前冻结，本批事件选择仍是 retrospective，必须保留该限制。

## 9. 内部执行批次

以下是同一 V3.0 产品环内部批次，不分别交 Codex。

### 9.1 Batch A：产品契约与最小摄入接线

- 冻结六子机制结构；
- 冻结类型 checkpoint 模板；
- 实现 Inbox → registry 最小一键接线；
- 保留来源字段；
- 验证 event_id 稳定和幂等；
- 不声明 RESULT PASS。

### 9.2 Batch B：结果记录与页面主路径

- 结果记录结构；
- 事前只读区；
- 实际事实区；
- 市场观察区；
- 路径复盘区；
- 保存、重开、复制摘要；
- 标签在页面可见；
- 不声明 RESULT PASS。

### 9.3 Batch C：样本绑定与真实路径验收

- 冻结样本绑定及 hash；
- 三条官方来源事件从 Inbox 纳入；
- `nfp_2026_01` 从既有 registry 打开；
- 完成四条机制路径；
- 生成六子机制矩阵；
- 生成 retrospective quality signal；
- Human 按清单走查；
- 形成 `EVENT_RESEARCH_RESULT_V1_READY`。

### 9.4 集中 R1

只有 A–C 全部完成后，建立一次 Codex R1：

- 审查完整产品路径；
- 审查六子机制证据；
- 独立重放关键反例；
- 检查声明隔离；
- PASS 或 CHANGES_REQUIRED。

不为内部 batch 分别开环。

3. 来源字段保存重开仍存在；
4. 历史样本标签清晰可见；
5. 无事前快照不会被补造；
6. legacy 样本不冒充 unseen；
7. 未来事件仍被事后门禁阻止；
8. 结果页可保存、重开和复制；
9. 六子机制分别显示；
10. 质量信号没有升级研究声明；
11. 单条正常复盘目标不超过十分钟；
12. 用户认为结果以后值得再次打开。

### 10.3 关键负向用例

- 重复导入不得创建第二个 event_id；
- 导入不得丢失官方来源；
- 事后保存不得改写事前快照；
- 无快照不得生成伪事前；
- RETROSPECTIVE 不得隐藏；
- LEGACY_EXPOSED 不得转 unseen；
- 任一研究结论升级尝试必须拒绝；
- 同日未来时间不得生成事后；
- 时间未知必须 fail-closed；
- checkpoint hash 不匹配时质量信号必须失效；
- 生成后修改模板不得重新包装旧结果。

## 11. R1 后轻量产品复盘

### 11.1 目的

R1 只判断本环是否按定义实现。

R1 后由 Human 再回答一次：

> 这轮到底解决了什么产品问题？

该节点避免“机制通过后自动继续扩展”，防止再次把 Workbench 做成复杂但无增量的系统。

### 11.2 三个问题

1. **少干活了吗？**  
   从真实来源到可用复盘，比手工建表减少了哪些动作？

2. **留下新资产了吗？**  
   一周后重开，这份结果是否仍提供可复用信息？

3. **剩余最大人工成本是什么？**  
   是来源导入、事实确认、市场窗口、路径判断，还是摘要整理？

### 11.3 决策结果

Human 只选择其一：

- `PROCEED_TO_V3_1`：RESULT 确有价值，进入 REGISTRY + BADGE；
- `REVISE_RESULT`：机制通过但产品价值不足，在 RESULT 内做一次产品修正；
- `STOP_V3_EXPANSION`：结果页没有形成增量，停止扩展。

该轻量复盘不自动触发第二次 Codex R1。只有新增风险、改变正式契约或形成新产品批次时再审核。

## 12. PASS 语义与声明边界

### 12.1 `EVENT_RESEARCH_RESULT_V1_PASS` 表示

- 六个机制子项全部 PASS；
- 真实摄入到 registry 的最小路径成立；
- 标签、事前/事后隔离和门禁成立；
- 结果可保存、重开和复制；
- Human 完成产品路径走查。

### 12.2 它不表示

- 历史复盘分析正确；
- 方法论可靠；
- 模型预测有效；
- 研究证据独立；
- 数据质量全面达标；
- 产品可以公开发布。

### 12.3 禁止联动升级

本环无论结果如何，均不得自动升级：

- `RESEARCH_PASS`
- `DATA_QUALITY_PASS`
- `RELEASE_PASS`
- held-out / forward 状态
- legacy 数据角色

## 13. 风险与控制

| 风险 | 控制 |
|---|---|
| 复合 PASS 隐藏具体失败点 | 六子机制独立判定和 reason codes |
| 已知结局影响指标选择 | 先冻结事件类型模板，再绑定事件 |
| retrospective 叙事过于容易 | 只输出有限 quality signal，不声明可靠性 |
| 事后污染事前 | 事前快照只读；无快照显式标记 |
| 历史样本被包装成预测成功 | RETROSPECTIVE + claim safety |
| legacy 被包装成 unseen | LEGACY_EXPOSED + 禁止角色升级 |
| 导入仍然靠手工建卡 | 最小 Inbox → registry 一键接线 |
| 摄入范围膨胀 | 不重写扫描器，不做全自动采集 |
| checkpoint 生成后被调整 | hash 绑定；修改则失效 |
| R1 PASS 后继续无目标扩展 | 强制 Human 轻量产品复盘 |

---

## 14. 回滚点

- Inbox → registry 入口可关闭，不影响现有日历纳入；
- RESULT 页面入口可关闭，不删除 registry 原记录；
- 新结果字段必须保持旧记录可读；
- 无法识别的新状态降级为未知，不损坏数据；
- checkpoint 工件是只读评估材料，不作为 registry 第二真相源；
- V3.0 回滚后，V2.2–V2.7 能力继续有效。
