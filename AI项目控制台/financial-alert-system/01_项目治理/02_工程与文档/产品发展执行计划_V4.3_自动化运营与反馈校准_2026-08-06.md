# 产品发展执行计划 V4.3：自动化运营与反馈校准

## 0. 定稿方向

V4.0、V4.1、V4.2 已分别完成结构化宏观、财报和 FOMC 的证据包、确定性分析、可审核草稿与简报接线。当前缺口不再是“有没有分析模块”，而是：

> 三条能力仍以分散入口和人工触发为主，系统没有持续完成整条流程，也没有量化哪些人工动作真正必要。

V4.3 不新增第四套分析引擎，而是把已有能力合流为一个日常自动化产品流程：

```text
事件进入 registry
→ 系统判断事件类型、阶段与自动化资格
→ 自动刷新已有正式证据
→ 自动运行既有确定性分析
→ 自动生成或更新事前/事后草稿
→ 正常项进入待确认队列
→ 异常项进入统一例外队列
→ Human 确认、修订或弃权
→ 系统统计人工差异并提出模板改进建议
```

本轮验证的是自动化机制、人工减负和反馈可审计性，不验证分析预测力。

## 1. 产品目标

用户打开每日简报后，应当直接知道：

- 哪些事件已经由系统自动处理完成；
- 哪些草稿只需确认；
- 哪些事件因缺来源、身份冲突、窗口不完整或验签失败需要人工；
- 系统具体完成了哪些步骤、使用了哪些输入版本；
- 人工修改了什么，以及修改原因是否会形成后续模板建议。

正常事件不要求用户手工点击“刷新证据”“生成草稿”或从空白填写；Human 仍保留最终确认、重要改写和弃权权力。

## 2. 核心产品原则

1. **复用而非重写**：宏观、财报、FOMC 继续使用各自已验收的来源、计算和草稿模块。
2. **规则先于模型**：事件身份、阶段、数据质量、是否可自动运行由确定性规则判断。
3. **正常项自动流转**：满足资格条件的事件自动到达“待确认”，不要求逐页操作。
4. **异常项集中处理**：缺失、冲突、过期和失败统一进入例外队列，不散落在各页面。
5. **反馈只形成建议**：人工修订不得自动改变事实来源、阈值、模板或研究结论。
6. **失败可见**：任何阶段失败都保留最后成功版本、失败阶段和原因，不把旧数据显示为最新。

## 3. 本轮范围

### 3.1 自动化编排

建立一个跨事件类型的日常运行入口，按既有模块顺序执行：

1. 识别 registry 中需要处理的事件；
2. 判断 `eligible / abstain / blocked`；
3. 调用相应的宏观、财报或 FOMC 证据刷新；
4. 运行既有确定性分析；
5. 生成或更新正确阶段的草稿；
6. 更新每日简报与例外队列；
7. 写入一次可回放的运行记录。

首版只提供人工触发的一键日常运行；正式后台定时调度必须另获 Human 授权，不作为本计划开环的默认权限。

### 3.2 自动化资格

事件只有同时满足以下条件才允许进入正常自动路径：

- `event_id`、事件类型、期次或会议身份明确；
- 存在该事件类型已批准的正式来源路径；
- 输入版本、可知时间和事件阶段可确定；
- 不存在关键身份冲突、hash/proof 失败或事前/事后污染；
- 输出目标为系统自动草稿，不覆盖人工版本。

不满足时必须进入 `ABSTAIN` 或 `BLOCKED`，并显示唯一主原因和建议动作。

### 3.3 统一例外队列

例外队列至少区分：

- 来源暂不可用；
- 身份或期次待核验；
- 正式证据损坏或验签失败；
- 关键字段或市场窗口不完整；
- 草稿生成失败；
- 人工修订后出现新证据，需要重新确认。

每项只给一个主动作，例如“核验身份”“查看来源”“保留弃权”“重新确认”，避免继续增加表单。

### 3.4 人工反馈与校准

系统只记录结构化差异：

- 自动草稿是否被直接确认；
- 哪些字段被修改、删除或补充；
- 修改原因属于事实纠正、证据补充、表达调整、结论保留或弃权；
- 从进入待办到完成使用了多少人工动作；
- 哪类事件、字段或理由码反复需要人工处理。

系统可以生成模板改进建议，但不得自动修改模板、阈值、来源 allowlist、排序规则或研究政策。

## 4. 最小数据记录

### 4.1 AutomationRun

```text
run_id
triggered_at
trigger_type
event_id
event_type
input_versions
stages[] { name, status, started_at, ended_at, reason, output_ref }
final_status
requires_human
rollback_ref
```

### 4.2 HumanDecisionRecord

```text
event_id
draft_kind
auto_version
auto_sha256
decision { confirmed | revised | abstained }
changed_fields[]
reason_codes[]
human_actions_count
decided_at
```

这两类记录只描述流程和修订，不成为新的事实真相源，也不保存密钥或受限原文。

## 5. 内部工作包

### Work A：人工负担基线与统一运行记录

- 用现有三个事件类型各选至少一个样本；
- 记录当前完成一次研究流程所需的点击、手填字段和等待步骤；
- 建立 `AutomationRun` 与失败阶段展示；
- 不改变现有分析结论。

### Work B：跨类型一键自动运行与例外队列

- 复用现有刷新、分析和草稿入口；
- 同一事件重复运行保持幂等；
- 正常项进入待确认，异常项进入例外队列；
- 浏览器关闭后重新打开仍能看到运行状态。

### Work C：人工修订差异与校准摘要

- 保存自动版本与人工版本差异；
- 统计直接确认率、修改字段和弃权原因；
- 形成只读校准摘要和模板建议；
- 不自动改变任何正式规则。

### Work D：真实产品走查

- 至少覆盖宏观、财报、FOMC 各两条事件，共不少于六条；
- 允许使用带明确 `RETROSPECTIVE` 标签的历史回放，不等待未来日期；
- 至少一条使用当前 registry 中的真实待处理事件；
- 对每条记录自动完成步骤、人工动作、异常和最终状态。

Work A–D 属于同一个产品切片，不分别建立审核节点。

## 6. 量化验收

全部满足才可声明 `EVENT_RESEARCH_AUTOMATION_V1`：

1. 三类事件各至少两条完成端到端走查，总样本不少于六条；
2. 符合自动化资格的样本中，至少 80% 无需手工刷新证据或点击生成草稿；
3. 正常路径单事件人工确认动作不超过 2 次；
4. 相对 Work A 基线，空白手填字段数量减少至少 70%；
5. 自动展示的正式事实 100% 带来源、版本、可知时间和事件身份；
6. 缺失、冲突、过期、验签失败和部分成功 100% 进入可见 `ABSTAIN/BLOCKED`；
7. 自动稿、人工稿和差异记录 100% 可重开；
8. 重复运行不重复创建事件、草稿或运行结果；
9. 测试与回放不写入正式产品数据根；
10. Human 能从简报在 10 秒内区分“直接确认”和“需要处理的例外”。

样本不足或基线无法形成时，结论为 `ABSTAIN`，不得通过降低目标补成 PASS。

## 7. 六个独立验收子机制

| 子机制 | 含义 |
|---|---|
| `AUTO_ELIGIBILITY` | 自动运行资格是否确定、可解释且 fail-closed |
| `PIPELINE_ORCHESTRATION` | 既有刷新、分析、草稿和简报是否按顺序幂等运行 |
| `EXCEPTION_ROUTING` | 异常是否集中、可见并给出正确人工动作 |
| `HUMAN_EFFORT_REDUCTION` | 人工动作和空白手填是否达到减负目标 |
| `REVISION_AUDIT` | 自动稿、人工稿、差异和原因是否可追溯 |
| `PRODUCT_CONTINUITY` | 重开、失败恢复和既有三类事件路径是否保持可用 |

复合验收报告必须分别列出六项状态，不得只写一个无法定位失败的布尔值。

## 8. 声明边界

`EVENT_RESEARCH_AUTOMATION_V1` 只表示：

- 已有宏观、财报和 FOMC 能力可由统一流程自动运行；
- 正常事件可以自动形成待审核草稿；
- 异常进入可见例外队列；
- 人工修订可审计，并达到本计划的人工减负指标。

它不表示：

- 自动分析具有预测力；
- 人工修订一定正确；
- `RESEARCH_PASS`、`DATA_QUALITY_PASS` 或 `RELEASE_PASS`；
- 已启用无人值守定时任务、云部署、自动发布或自动交易。

## 9. 明确不做

- 不新增事件类型、数据源类别或第四套分析引擎；
- 不重写 registry、每日简报、研究记录或收尾卡；
- 不建设新数据库、消息队列或云调度平台；
- 不让模型自主浏览并写入正式事实；
- 不自动学习或自动调整阈值、模板、排序和研究规则；
- 不做预测准确率、策略收益或 `RESEARCH_PASS` 验收；
- 不做 Lovable、Render 或其他部署；
- 不为命名、样式、更多测试、性能或内部重构延长产品环。

## 10. 风险、停止与回滚

出现以下任一情况立即停止自动流转并回退到现有人工路径：

- 证据绑定到错误事件、期次或时间；
- 自动稿覆盖人工内容；
- 失败被显示为成功或旧证据被显示为最新；
- 重复运行产生重复事件或不可恢复的状态；
- 测试写入正式产品数据；
- 自动流程没有减少人工动作。

回滚只关闭 V4.3 编排、例外队列和反馈统计；V4.0、V4.1、V4.2 已验收的单类型路径继续可用，已有事件、证据、草稿和人工修订不得删除。

## 11. 审核预算

- 计划确认不等于执行开环；
- Work A–D 连续完成，不逐段交 Codex；
- 完整产品切片结束后最多一次集中产品复审；
- 若存在真正阻断项，只允许一次最小修复及一次最终复审；
- 最终仍未通过时直接交 Human，停止自动技术循环；
- 只有事实错误、事件错绑、数据污染、安全、覆盖人工内容、主路径阻断或越权声明可以阻断；
- 其他问题登记技术债，并在 Human 产品复盘中决定是否值得处理。

## 12. 开环条件与第一步

当前状态：`planned_not_open`。本计划落盘不改变 V4.2 `done/human` 的当前执行入口。

只有以下条件全部满足才开 `PRD-EVENT-AUTOMATION-16`：

1. Human 明确回复“开启 V4.3”；
2. 指定本轮允许读取与写入的正式数据面；
3. 明确首批六条事件样本；
4. 锁定开环业务 baseline；
5. 工作树无未归属变更；
6. 正式后台定时调度若需要启用，另行明确授权。

开环后的第一步仅做 Work A：记录当前人工负担基线和既有入口，不先重写编排器。
