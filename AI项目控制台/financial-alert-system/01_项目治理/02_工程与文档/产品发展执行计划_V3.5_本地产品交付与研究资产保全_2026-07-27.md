# 产品发展执行计划 V3.5：本地产品交付与研究资产保全

## 0. 定稿结论

V3.5 是 V3 产品阶段的最后一个能力环，解决：

> 用户能否通过一个入口稳定打开今日简报，并把 V3 事件研究资产导出，在隔离目录恢复后继续打开和使用。

本环不增加新的事件分析功能，不上云，不重写数据库。

## 1. 用户主路径

```text
启动本地产品
→ 自动进入今日简报
→ 查看真实数据目录和备份状态
→ 导出研究资产
→ 查看资产清单和排除项
→ 在新的隔离目录恢复
→ 使用独立端口打开台账、研究记录和收尾卡
→ 停止恢复实例
→ 确认原产品和原资产未受影响
```

## 2. 产品决策

### 2.1 唯一推荐入口

新增：

- `start_local_product.bat`
- `stop_local_product.bat`

复用现有端口所有权保护，默认端口 `8013`，默认打开 `daily_briefing.html`。

现有 `start_cc13_local.bat`、`start_prod01_local.bat` 保留兼容，但不再作为推荐入口。不得继续默认打开 `nfp_2099_01` 示例切片。

### 2.2 产品资产边界

默认打包：

- `event_research_registry`
- `event_result_v3`
- `prep_checklist`
- `briefing_actions`
- 经确认属于用户研究成果的 `analysis_archive`

只记录引用、默认不嵌入：

- 本地证据和外部来源引用
- NFP 卡片与研究运行引用

明确排除：

- `.env`、密钥和访问令牌
- `remote_cache`
- 新闻缓存全文
- 测试截图、smoke 工件、日志和临时文件
- `nfp_research`、raw 数据和 held-out/forward 材料
- `node_modules`

V3.5 保护的是 V3 事件研究产品资产，不代表整个仓库或 RES 研究资产已经完成灾备。

### 2.3 最小数据根切换

增加单一配置：

`FAS_PRODUCT_DATA_ROOT`

未设置时继续读取仓库内 `data`；恢复演练时指向隔离目录。

该配置只影响本计划列出的产品资产，不重定向代码、模板、缓存或 NFP 研究库。这是 V3.5 唯一允许的基础接线，不扩展为存储架构重写。

### 2.4 恢复不覆盖

V3.5 第一版只允许恢复到：

- 不存在的目录；或
- 已存在但为空的目录。

不提供合并、覆盖和冲突解决。

## 3. 执行批次

### Batch A：启动与连续性页面

- 收敛唯一推荐启动、停止入口；
- 默认进入今日简报；
- 提供“本地产品与备份”页面；
- 显示产品数据目录、资产数量、最近成功备份和来源状态；
- 端口冲突、目录不可读和启动失败必须使用用户可理解的提示。

### Batch B：资产导出与清单

- 用户显式触发导出；
- 生成单一资产包和 `manifest.json`；
- 清单包含相对路径、大小、SHA-256、产品版本、生成时间和资产数量；
- 明确区分已包含、仅引用、明确排除；
- 任何读取、哈希或秘密文件检查失败均不得显示备份成功。

### Batch C：隔离恢复与真实走查

- 选择刚生成的资产包并先显示恢复预览；
- 只恢复到新的空目录；
- 校验路径、清单和全部 SHA-256；
- 使用独立端口及隔离产品数据根启动；
- 打开同一 `event_id` 的台账记录、研究记录、收尾卡和准备清单；
- 停止隔离实例；
- 比较原始产品资产前后 SHA-256；
- 只做一次集中产品验收。

## 4. PASS 标准

全部满足才可写入 `LOCAL_PRODUCT_CONTINUITY_V1_PASS`：

- 一个入口即可启动并进入今日简报；
- 停止操作只关闭本产品拥有的实例；
- 用户能看到真实产品数据目录和最近备份状态；
- 资产包不包含密钥、缓存新闻全文或测试工件；
- manifest 与实际文件、数量和 SHA-256 一致；
- 引用但未打包的资产明确可见；
- 恢复目标必须为空，不会覆盖原数据；
- 隔离恢复后可打开同一 `event_id`；
- 研究记录、收尾卡和准备清单内容一致；
- 隔离实例与原产品使用不同端口；
- 停止或删除隔离恢复目录不影响原产品；
- 原始产品资产前后 SHA-256 一致；
- Human 能在五分钟内完成“导出—恢复—打开验证”。

## 5. P1 阻断边界

只有以下问题可以阻断 PASS：

- 原始资产可能被修改或覆盖；
- 资产包包含密钥或受限内容；
- manifest、文件数量或哈希不一致；
- 恢复后事件身份、研究记录或收尾卡无法打开；
- 启停操作可能关闭其他端口或其他程序；
- 页面显示备份成功，但实际导出或恢复失败。

文案、布局、更多格式、性能优化和附加负向用例登记为后续事项，不追加验收轮次。

## 6. 明确不做

- 不上云；
- 不做账号、权限和多人协作；
- 不做自动远程同步或后台定时备份；
- 不做原目录覆盖恢复；
- 不重写数据库；
- 不备份整个仓库；
- 不把 V3.5 升级为灾备系统；
- 不宣称 `RESEARCH_PASS`、`DATA_QUALITY_PASS` 或 `RELEASE_PASS`；
- 不自动开启 V4.0。

## 7. 审核方式

- Batch A/B/C 由 Cursor 连续完成，不分段开启审核；
- 完整切片完成后进行一次集中 R1；
- 若存在 P1，只允许一次定向修复和一次最终确认；
- 非 P1 登记后续事项，不拖延产品主线；
- 最多三个评审 turn，仍有阻断则交 Human 决策。

## 8. 完成后的决策门

V3.5 完成后，V3 产品发展阶段正式结束。Human 重新选择：

1. 日常使用和维护；
2. 回到真实 forward / 研究有效性轨道；
3. 规划 V4 多人协作或云部署；
4. 暂停扩展，积累真实使用反馈。
