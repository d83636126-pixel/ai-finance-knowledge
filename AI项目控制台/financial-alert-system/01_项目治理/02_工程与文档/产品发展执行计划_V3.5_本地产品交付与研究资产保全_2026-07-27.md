# 产品发展执行计划 V3.5：本地产品交付与研究资产保全

## 0. 定稿结论

当事件摄入、复用和每日简报完成后，下一问题不再是增加页面，而是：

> 用户能否稳定启动产品、知道数据保存在哪里，并在换机器、误操作或升级后恢复自己的事件研究资产。

V3.5 是产品连续性，不是新架构、上云或多人系统。

## 1. 用户主路径

```text
一键启动
→ 自动打开今日简报/事件台账
→ 查看本地数据与来源状态
→ 导出研究资产包
→ 在独立临时目录恢复
→ 打开事件、研究记录和收尾卡
```

## 2. 产品范围

### 2.1 一键启动与停止

- 单一推荐启动入口；
- 默认打开产品主页或今日简报；
- 端口冲突、数据目录错误和服务失败可见；
- 停止动作只关闭本产品实例。

### 2.2 用户可理解的设置

只展示用户需要的设置：

- 本地数据目录；
- Obsidian 目录；
- 日历和 Inbox 来源状态；
- 默认打开页面；
- 备份位置；
- 最近一次成功备份。

不向用户暴露内部包、测试门禁或研究评分。

### 2.3 研究资产导出

资产包至少包含：

- registry 事件身份；
- 研究记录和 refs；
- V3 收尾卡；
- 用户创建的事实节点和准备清单；
- 简报处理状态；
- 清单、版本和 SHA-256。

不默认包含密钥、访问令牌、缓存新闻全文或无关测试工件。

### 2.4 可验证恢复

- 只能恢复到用户明确选择的目录；
- 恢复前显示将写入的内容；
- 不覆盖现有数据，除非用户明确确认；
- 恢复后运行完整性检查；
- 至少打开一条事件、一条研究记录和一张收尾卡。

## 3. 执行批次

### Batch A：启动与设置

- 收敛推荐启动入口；
- 建立产品级错误提示；
- 设置页只显示必要信息。

### Batch B：导出与清单

- 生成可携带资产包；
- 排除密钥和临时文件；
- 提供内容清单与哈希。

### Batch C：隔离恢复演练

- 在新的临时数据目录恢复；
- 检查事件、记录、收尾卡和来源链；
- 验证停止与回滚；
- 一次集中产品验收。

## 4. PASS 标准

全部满足才可写入 `LOCAL_PRODUCT_CONTINUITY_V1_PASS`：

- 用户通过一个入口启动并进入产品；
- 常见启动失败原因可理解；
- 用户知道真实数据目录和最近备份状态；
- 资产包不包含密钥；
- 导出清单与实际文件一致；
- 在隔离目录恢复成功；
- 恢复后事件身份、研究记录和收尾卡可打开；
- 原数据目录未被覆盖；
- 回滚可以删除隔离恢复目录而不影响原产品。

## 5. 明确不做

- 不上云；
- 不建设账号与权限；
- 不做自动远程同步；
- 不做应用商店发布；
- 不重写数据库；
- 不把研究工件全部打包；
- 不宣称灾备级 SLA；
- 不并行 V4.0。

## 6. 回滚与停止条件

- 新启动入口失败时保留现有启动方式；
- 导出失败不得产生“备份成功”状态；
- 恢复只能在已验证的隔离目录执行；
- 任何原始数据覆盖风险均阻断 PASS。

## 7. V4.0 决策门

V3.5 归档后，不自动继续开发。Human 重新选择：

1. 继续单用户本地产品；
2. 单独启动研究有效性/forward 轨道；
3. 评估多人协作或云部署；
4. 停止扩展，只维护现有产品。

V4.0 必须另写路线图，不能由 V3.5 自动继承范围。
